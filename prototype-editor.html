Rust 异步编程：从零开始的 async/await 实战

Rust 的异步编程模型是零成本抽象的典范——你在编写直观的 async/await 代码时，编译器会将其转化为高效的状态机，没有运行时开销。

为什么选择 async Rust？

传统的多线程模型为每个连接分配一个完整的线程栈（通常 2-8MB），在高并发场景下内存消耗巨大。异步模型则允许你在少量线程上运行成千上万个任务：

特性多线程模型异步模型
并发单位OS 线程Future/Task
内存开销~2-8MB/连接~几百字节/任务
调度方式内核调度用户态调度

基础用法

use tokio;

#[tokio::main]
async fn main() {
    let result = fetch_data("https://api.example.com").await;
    println!("Got: {}", result);
}

async fn fetch_data(url: &str) -> String {
    // 模拟异步操作
    tokio::time::sleep(Duration::from_secs(1)).await;
    format!("Response from {}", url)
}
关键点：.await 不会阻塞线程，它只是告诉运行时「这个任务在等待 IO，你可以去执行其他任务」。

实战：构建异步 HTTP 服务器

使用 hyper 和 tokio 构建一个高性能的 HTTP 服务器：

use hyper::{Body, Request, Response, Server};
use hyper::service::{make_service_fn, service_fn};
use std::convert::Infallible;
use std::net::SocketAddr;

async fn handle(req: Request<Body>) -> Result<Response<Body>, Infallible> {
    match req.uri().path() {
        "/" => Ok(Response::new(Body::from("Hello, async Rust!"))),
        "/api/status" => Ok(Response::new(Body::from(r#"{"status":"ok"}"#))),
        _ => Ok(Response::builder()
            .status(404)
            .body(Body::from("Not Found"))
            .unwrap()),
    }
}

这段代码展示了 async Rust 的优雅之处：模式匹配处理路由、零拷贝的 Body 类型、以及编译期就保证的类型安全。
