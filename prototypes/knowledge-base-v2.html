RAG Architecture

Overview

Retrieval-Augmented Generation (RAG) is a technique that enhances LLM outputs by retrieving relevant information from external knowledge sources before generating a response. Unlike fine-tuning, which modifies model weights, RAG keeps the model frozen and augments its context window.

Architecture Components

A typical RAG system consists of three main stages:

  • Indexing — documents are split into chunks, embedded, and stored in a [[Vector DB Comparison|vector database]]
  • Retrieval — the query is embedded and matched against the index to find relevant chunks
  • Generation — retrieved chunks are combined with the prompt and fed to the LLM

Embedding Models

The choice of [[Embedding Models|embedding model]] significantly impacts retrieval quality. Models like OpenAI's text-embedding-3 and sentence-transformers provide dense vector representations that capture semantic meaning.

"The retrieval step is the bottleneck. No matter how good your LLM is, if the context is missing, the answer will be wrong." — Karpathy

Comparison with Fine-tuning

While fine-tuning changes the model's internal weights to adapt to a specific domain, RAG leaves the model unchanged and instead enriches the prompt. This makes RAG more suitable for:

  • Rapidly changing knowledge (news, documentation)
  • Multi-domain applications where a single model serves many topics
  • Scenarios requiring source attribution
