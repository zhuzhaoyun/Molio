# Molio vs Obsidian — 知识库功能全面对比

> 对比日期：2026-06-15
> 
> Obsidian 版本参考：Obsidian v1.8+（桌面端）
> 
> Molio 版本：当前开发版本

---

## 一、核心理念对比

| 维度 | Obsidian | Molio |
|------|----------|-------|
| **定位** | 纯知识管理工具 | AI 工作站（知识管理 + AI 创作 + 多平台发布） |
| **知识管理哲学** | "你的第二大脑" — 以 Markdown 文件为核心，手动整理 | "AI 优先的知识库" — AI 自动构建、维护、查询 Wiki |
| **用户角色** | 用户是**手动整理者** | 用户是**策展人/审核者**（AI 做脏活，用户把关） |
| **对用户的认知要求** | 需要学习 Zettelkasten、链接思维等方法论 | 知识管理由 AI 驱动，用户只需要审核结果 |
| **核心理念** | "你的笔记你做主"（You own your notes） | "你的知识 AI 帮你管" |

## 二、Vault / 存储管理

| 特性 | Obsidian | Molio |
|------|----------|-------|
| **Vault 概念** | 本地文件夹 = 一个 Vault | 同样以本地文件夹为 Vault |
| **多 Vault 管理** | 切换需打开不同窗口 | 同一个窗口内下拉/弹窗切换 |
| **Vault 创建** | 手动选择文件夹 | 支持原生目录选择器（Electron）+ 手动输入 |
| **文件存储** | 纯文件系统，元数据存 `.obsidian/` | 纯文件系统，元数据存 SQLite |
| **Vault 删除** | 删除 `.obsidian/` 配置 | 仅删数据库记录，**不清除文件**（解除关联语义） |
| **跨 Vault 关联** | 不支持 | 不支持 |
| **Vault 数量上限** | 不限 | 不限 |

**关键差异**：
- Obsidian 每个 vault 独立窗口，Molio 统一窗口内切换（类似 VS Code 多项目）
- Molio 的 vault 删除是"解除关联"语义，不碰磁盘文件，更安全
- Obsidian 元数据存 `.obsidian/` 目录，Molio 存 SQLite

## 三、文件浏览与操作

| 特性 | Obsidian | Molio |
|------|----------|-------|
| **文件树** | 左侧边栏 | `KbFilePanel` |
| **文件搜索** | 实时过滤（按文件名） | 客户端搜索过滤 |
| **新建文件/文件夹** | 右键菜单 + 侧边栏按钮 | 同 |
| **重命名** | 右键 → 重命名 | 内联重命名（点击文件名，自动选中不含扩展名部分） |
| **删除确认** | 系统 confirm | 自定义 ConfirmDialog |
| **拖拽移动** | 文件树内拖拽 | **暂不支持** |
| **右键菜单** | 丰富（打开/新建/重命名/删除/复制/移动） | 功能较基础（打开/新建/重命名/删除） |
| **标签栏** | 多标签页 | `KbTabBar`，支持中键关闭 |
| **文件排序** | 多种排序（字母/创建时间/修改时间） | 固定排序：目录优先 + 字母序 |
| **支持的文件类型** | Markdown 为主 + 图片 + PDF（插件） | .md/.txt/.html/.json/.yaml + 图片 + PDF/Office |
| **外部文件变更检测** | 实时检测 | 窗口聚焦时延迟 1 秒刷新 |

## 四、编辑器体验

| 特性 | Obsidian | Molio |
|------|----------|-------|
| **编辑模式** | 源码 / 实时预览 / 阅读 | 阅读 / 编辑(CodeMirror 6) / 排版(三栏) |
| **实时预览** | 所见即所得（Live Preview） | 分栏实时预览（左编辑右预览） |
| **源码模式** | 有 | CodeMirror 6 |
| **WYSIWYG** | Live Preview 是 WYSIWYG | 分栏模式，编辑与预览分离 |
| **Vi/Vim 模式** | 内置 | 无 |
| **格式化快捷键** | 完整 | Ctrl+B/I/K/E/D/1/2/3 |
| **富文本排版** | 无（纯 Markdown） | **三栏排版编辑器**（doocs/md） |
| **样式控制** | 依赖主题 CSS | **样式面板**：字体/字号/颜色/主题/代码主题/标题样式 |
| **CSS 内联** | 无 | `juice` 运行时内联，用于发布 |
| **移动端预览** | 响应式 | 切换移动端宽度 (375px) |
| **内联图片** | 有 | 有 |
| **Markdown 渲染** | marked（旧版）+ 社区插件 | **marked v18** + 12 扩展（KaTeX/Mermaid/PlantUML/脚注/TOC/alert） |

**核心差异**：Obsidian 的编辑器以**写作体验**为核心（WYSIWYG）；Molio 的编辑器以**排版发布**为核心（三栏 + 样式面板 + CSS 内联 = 为多平台发布准备）。

## 五、Wiki 链接系统

| 特性 | Obsidian | Molio |
|------|----------|-------|
| **Wikilinks** | `[[Page]]` | `[[Page]]` |
| **链接别名** | `[[Page\|别名]]` | 正则解析支持 |
| **块引用 / 段落链接** | `[[Page#^block-id]]` | 仅文件级链接 |
| **未创建页面检测** | 灰色显示（指向不存在的文件） | 死链接检测（图谱 + lint） |
| **反向链接面板** | 右侧边栏，显示谁链接了当前页 | **无独立反向链接面板** |
| **出站链接面板** | 显示当前页链接了谁 | 无 |
| **链接建议** | 输入 `[[` 时自动补全 | **暂不支持** |
| **标签系统** | `#tag` 自动收集，标签面板 | Wiki frontmatter 中的 `tags` 字段 |
| **Properties (frontmatter)** | YAML frontmatter，支持表格视图 + 内联编辑 | frontmatter schema + **可折叠属性卡片**（折叠态：类型标签；展开态：完整字段 + [[wikilink]] 跳转）<br>⚠️ 属性编辑：**待实现** — 需引入 `js-yaml` 做序列化回写 |
| **页面关系图** | 基于链接的图 | 图谱构建 + 可视化 |

## 六、知识图谱

| 特性 | Obsidian | Molio |
|------|----------|-------|
| **图谱可视化** | 原生（d3.js 基础） | Sigma.js + ForceAtlas2 |
| **节点大小** | 根据链接数 | 根据 `linkCount` |
| **交互操作** | 拖动、缩放、悬停高亮 | 拖动、缩放、悬停高亮、**双击导航到文件** |
| **筛选节点** | 支持 | 无 |
| **全局/局部图** | 全局图 + 局部图（当前文件） | 全局图 |
| **Minimap** | 无 | 右下角缩略图 |
| **死链接标记** | 灰色显示但不显式标记 | 后端死链接检测 + lint 报告 |
| **图谱数据来源** | 实时解析 vault 内全部 `.md` 文件 | 同上，链接解析：精确匹配 → basename 匹配 → 同目录优先 |

Molio 的图谱交互虽稍弱，但后端**单独做了一层死链接检测**，这是 Obsidian 没有的设计。

## 七、AI 能力（核心差异区）

| 特性 | Obsidian | Molio |
|------|----------|-------|
| **内置 AI** | 无（需要插件 + 自配 API key） | **原生深度集成** |
| **AI Wiki 构建** | 无 | AI 扫描源文件自动生成结构化 Wiki |
| **AI 增量导入** | 无 | 将新文件融入已有 Wiki，自动交叉链接 |
| **AI 健康检查** | 无 | 12 项 lint 检查（孤立页面、断链、过时内容等） |
| **AI 问答** | 社区插件（Smart Connections 等） | 原生 Wiki Query（Wiki 优先，溯源回源文件） |
| **AI 对话归档** | 无 | 将 AI 对话内容提炼为 Wiki 页面 |
| **AI 运行时选择** | 无 | 支持 Claude Code / Codex / Gemini / Qwen 四种引擎 |
| **多轮 AI 对话** | 无 | 在 Wiki 聊天面板内与 AI 多轮交互 |
| **工具使用（读文件/搜索等）** | 无 | AI 可使用工具，用户可审批工具结果 |
| **重复内容检测** | 无 | `[!contradiction]` 矛盾标记 |
| **知识空白检测** | 无 | Lint 报告包含知识空白分析 |

**Molio 对 Obsidian 最大的差异化优势** — Obsidian 本质上是一个**手动工具**，AI 依赖社区插件且体验割裂；Molio 的 AI 是**原生内置**的，覆盖知识管理的完整生命周期（创建→维护→查询→归档）。

## 八、发布能力

| 特性 | Obsidian | Molio |
|------|----------|-------|
| **官方发布** | Obsidian Publish（付费 $10/月） | 无 SaaS 发布 |
| **发布平台** | 托管为静态网站 | **30+ 内容平台**（微信/知乎/CSDN/掘金/Medium 等） |
| **发布方式** | 上传到 Obsidian 服务器 | 通过 COSE Chrome 扩展注入到各平台编辑器 |
| **排版控制** | 主题 CSS | 样式面板 + CSS 内联 + 预览 |
| **Copy as HTML** | 社区插件 | **原生支持**（剪贴板 HTML+纯文本双格式） |
| **微信公众号适配** | 无 | CSS 内联保证微信编辑器兼容 |
| **定时发布** | 无 | 无 |
| **图床支持** | 无 | 无 |

**差异点**：Obsidian Publish 是**建站**（公开知识库），Molio 是**内容分发**（发布到各内容平台）。二者的发布方向完全不同。

### 用户画像差异

| | Obsidian 适合 | Molio 适合 |
|--|--------------|------------|
| **你的角色** | 知识管理重度用户、愿意手动整理 | 内容创作者、自媒体、AI 驱动工作流偏好者 |
| **你的工作流** | 阅读 → 手动笔记 → 链接 → 回顾 | 阅读 → **AI 自动整理** → 排版 → **一键发布** |
| **典型用户** | 研究员、学生、PKM 爱好者 | 技术写作者、公众号运营、多平台作者 |

### Molio 差异化路线

```
Obsidian:    文件夹管理 → 手动笔记     → 手动链接  → 插件增强
                                               ↑
Molio:       文件夹管理 → AI 自动整理   → AI 维护  → 一键排版 → 一键发布到 30+ 平台
               (共享)      (差异化)      (差异化)    (差异化)     (差异化)
```

**Molio 在以下场景优于 Obsidian**：
1. 有很多源文件需要转成结构化知识 → AI Build/Ingest
2. 需要定期发布到各内容平台 → 排版 + COSE 发布
3. 希望 AI 帮你维护知识库质量 → Lint + 矛盾检测
4. 想要在应用内完成"收集→整理→创作→发布"全流程

**Molio 目前弱于 Obsidian 的地方**：
1. 编辑器写作体验（Live Preview vs 分栏）
2. 搜索能力（最大的功能缺口）
3. 插件生态（路线选择，短期难追）
4. 反向链接和出站链接面板
5. 移动端支持
6. 社区和模板资源
