# 资源商品详情页：搜索意图承接与销售转化设计依据

> 日期：2026-10-26
> 状态：已接入发布链路与生产 SSR（2026-10-27）；新增资源随发布提交结构化内容。
> 适用范围：高中数学、史记、刑法考试、红楼梦等体系化知识库，兼容免费和付费资源。
> 前置讨论：[资源被发现路径讨论](2026-10-25-resource-discovery-discussion.md)。涉及冲突时，以本文记录的后续决策为准。

## 1. 目标与核心决策

资源当前难以触达潜在用户。需要通过用户搜索、联网 AI 问答等公开路径，让用户发现具体资源，进入商品详情页，并判断是否获取或购买。

**承接搜索意图的主体是商品详情页本身。** 将有价值的知识内容、问题解答和内容范围直接放进商品正文，既提供可检索、可引用的信息，又证明资源价值。不以新增选题博客再导流商品作为本次方案主线。

最终目标是资源获取和付费销售。搜索曝光、收录、AI 引用只是中间指标，页面须清楚解释资源是什么、能做什么、完整版本包含什么，以及如何使用。

### 已确认的边界

- 资源是抽取、整理和关联之后的**体系化知识库**，不是教材章节摘要的简单拼接。
- 教材、书籍的册次与章节是来源及辅助定位，不能成为所有商品的固定组织主轴。
- 通用模板统一信息层次，不预设某一学科的内容结构。数学可以按知识领域，史记可以按人物、事件、制度，红楼梦可以按人物、家族、情节、意象组织。
- 用户主要通过移动端访问，按移动端优先设计；桌面布局是扩展。
- 免费与付费资源共用模板。通用文案不默认用户必须付款。
- 页面可以覆盖同一资源下的多种相关问题，不机械遵循“一页只能承接一个狭窄关键词”。但不能因想覆盖关键词而虚构资源内容。

## 2. 内容如何决定

先核对实际资源，再把搜索意图映射到商品正文：

> 用户查询或提问 → 资源内对应知识 → 详情页展示区块 → 公开内容边界 → 完整资源价值

选取内容时同时检查：

1. 用户是否存在这一问题或资料需求，有什么证据？
2. 知识库是否实际包含相应内容，质量是否足以公开？
3. 页面能否给出实质答案，而不只是声称“本库支持”？
4. 这段答案是否能帮助用户理解完整资源的用途？

搜索结果、公开讨论、自动补全等可作定性证据，不能当作搜索量。模拟 AI 提问应标为测试题，不能宣称来自真实用户日志。

原型中的数学主题分组是为商品页查阅重新组织的视图，不改变源知识库。正式实现应允许编辑、校验分组，而不是通过文件名关键词自动分类后直接发布。

## 3. 通用商品页结构

### 3.1 首屏：价值与交付摘要

必须快速回答：这是什么、适合谁、能用来做什么、是什么交付形式。

- 资源名称与清楚的产品类型，例如“高中数学体系化知识库”。
- 简短用途说明，围绕学习、研究、写作、备课等真实任务。
- 经核实的规模或内容指标，不固定要求每个资源都有“概念页”和“对比页”。
- 格式信息，避免把本地 Markdown 知识库误认为纸质书、PDF 教辅或在线课程。
- 通用价值说明：**“已整理成体系，供你直接使用”**。不再使用“买到的是整理好的知识体系”。
- 价格/免费状态、主要获取动作，以及查看交付说明的入口。

### 3.2 典型问题与真实解答

直接用知识库内容回答用户可能搜索或向 AI 提问的问题。可采用问题标题、简明结论、解释、例子或反例等形式。

这些是知识问题，不是“怎么下载、如何支付”的购买 FAQ。两者分开。

公开解答应能独立理解，不能只有摘要和购买链接。明确摘编来源，避免将编写的示例冒充资源原文。

解答后自然说明：这是完整资源的哪一部分，完整资源还提供什么相关内容。提供交付说明或获取入口，不用打断阅读的弹窗促销。

### 3.3 知识关联与对比

展示体系化整理的实际价值，例如概念间的推导、人物与事件关系、相近罪名的构成要件对照。

- 可以是关系链、对照、带解释的关联条目。
- 不强制所有资源都有对比模块；可用真实关系链替代。
- 不为了“体系化”的外观画没有实质解释的节点图。
- 移动端优先纵向表达，避免只能缩放才能阅读的大图或宽表。

### 3.4 知识体系与内容范围

按知识主题组织概念、实体及相关内容，回答“我需要的东西是否在里面”。

- 每个主题有简短范围说明，不能只有关键词堆砌。
- 提供真实条目名称、展开查阅与搜索。
- 条目名称不等于已公开完整知识页正文，展示范围需明确。
- 若条目可点击，必须有实际目标；不能把不可用的标签伪装成链接。
- 完整目录可折叠，移动端不默认铺开数百条。
- 册次、章节可保留为来源或辅助筛选，不作为统一模板字段。

### 3.5 适用场景与完整资源价值

说明不同人群如何使用这份资源，并清楚区分公开试读和完整交付。

付费理由来自实际整理成果：更广的内容覆盖、成体系的关联、可反复使用的本地文件等。不得编造更新承诺、节省小时数、提分效果、评价或稀缺性。

### 3.6 交付、来源与使用说明

- 内容清单、格式、必要软件与使用步骤。
- 是否需要另行配置 AI 环境；不能让用户误以为购买资料即包含 AI 服务。
- 作者/整理方、资料基础、版本与真实更新日期。
- 明确资源边界，例如知识资料不等于题库或授课服务。
- 免费与付费状态、价格、实际获取方式。
- 购买/使用 FAQ。

上述模块组成通用模板；具体名称和顺序可微调，不能为保持版式而填充不存在的内容。真实内容预览可融入问题解答和关联模块，无需再重复一整块相同正文。

## 4. 免费与付费资源

| 项目 | 付费资源 | 免费资源 |
|---|---|---|
| 状态 | 显示实际价格 | 明确显示“免费” |
| 主要按钮 | “购买完整知识库”或真实购买动作 | “免费获取知识库”或真实获取动作 |
| 完整资源说明 | 解释付费交付比公开试读多什么 | 说明免费包包含什么及使用方式 |
| 通用价值文案 | 已整理成体系，供你直接使用 | 相同 |

按钮文案须与真实流程相符。若需要登录、付款或其他步骤，应在合适位置说明；不凭空新增门槛。免费资源不展示支付控件或“购买后解锁”等付费文案。

## 5. 移动端与内容可读取性

- 窄屏单列，正文、公式、对比示例可在手机宽度内阅读。
- 价格/免费状态及获取按钮固定底部，预留正文底部空间与安全区。
- 内容导航可吸顶，锚点落位不能被导航挡住。
- 长目录按主题折叠，搜索有匹配反馈及空态，清空后恢复默认状态。
- 不以减少手机首屏内容为由删除重要商品信息。
- 折叠内容也应存在于首个服务端 HTML 中，而不是点击后才请求正文。
- 搜索筛选只影响展示；无需执行 JavaScript 也应能读取主要商品信息、试读与内容范围。
- 桌面可以使用侧边购买信息，不能将桌面双栏直接缩小到手机。

## 6. SEO / GEO 上线边界

这是一种让商品内容更容易被理解、检索和引用的设计，不保证排名、收录、AI 引用或销售结果。

正式开发应：

- 合入原有商品 URL，避免仅为新版文案另造重复商品页。
- 正确输出标题、描述、canonical、服务端正文及对应内部链接。
- 保留并核对 Product、Offer、Breadcrumb 等适用结构化数据，价格和免费状态与可见内容一致。
- 不为 GEO 强制添加 Dataset 或 FAQPage；仅在内容与适用规则吻合时使用。
- 检查 robots、页面索引指令、实际响应及所需搜索爬虫访问权限。
- 区分搜索抓取与模型训练抓取，不能将二者视为同一件事。
- 上线后分开观察抓取、索引、目标查询曝光、访问、资源获取/支付与 AI 引用样本。

本地原型包含 `noindex,nofollow`，且运行于 localhost，这是预览保护，**不能原样带到正式商品页**。

参考：
- [Google：AI features and your website](https://developers.google.com/search/docs/appearance/ai-features)
- [OpenAI：爬虫用途与控制](https://developers.openai.com/api/docs/bots)

具体平台规则在上线前重新核对。

## 9. 开发验收

### 内容与通用性

- 可用同一模板配置数学、历史、文学、考试类资源，不改模板代码即可切换主题。
- 无对比内容时能合理省略或替换，不生成空区块。
- 免费、付费两类资源的价格、按钮、FAQ 和获取流程一致且正确。
- 数量与实际交付匹配，示例有来源，未核实的能力不作承诺。
- 完整资源与公开内容的区别清楚，用户能判断是否需要获取。

### 页面与交互

- 重点验证 360/390/430px 手机宽度，并检查桌面布局。
- 无意外横向溢出，公式和对比内容可读，底部按钮不遮挡最后内容。
- 导航、搜索、折叠、空态、清空恢复及获取按钮流程正确。
- 主要交互具备可访问名称和稳定的测试定位。

### 技术与验证

- 首个 HTML 包含核心内容；结构化数据与页面事实一致。
- 发布字段经过创建、编辑、保存、重新加载及 SSR 渲染仍完整保留。
- 接入生产代码时遵循对应包 AGENTS.md 的测试要求，UI 修改同步测试；若触及核心流程文件，执行仓库规定的全量 E2E。
- 区分“本地实现”“已部署”“已收录”“观察到效果”，不互相替代。

## 11. 实施状态（2026-10-27）

发布链路已接通，新增资源不再停在「模板支持字段但发布端始终写空」：

- 「AI 一键配置」同时起草元数据与 `MarketContent` 草稿（定位、关键事实、内容范围、典型问题、真实样例、交付说明、来源与核对、SEO）。
- 发布表单可展开编辑全部字段；首发随 `POST /market/listings` 落库，更新模式通过 `POST /market/listings/:id/content` 单独保存，不重传知识库 zip。
- 云端对发布者提交的内容做与管理员同一套校验；AI 草稿固定 `review.status = "draft"` 且 `review.autoDrafted = true`，官网与应用内详情会提示仍在核对；存量人工 draft 不提示。
- 应用内详情页同样渲染 `MarketContent`，社区条目不再只剩一句简介。
- 未生成内容时仍回退旧的 `summary + overview + highlights` 渲染，AI 不可用不阻断发布。
