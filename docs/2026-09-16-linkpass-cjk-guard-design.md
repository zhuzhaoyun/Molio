# wiki 链接对账：中文词中保护与坏尾巴清理 —— 行为说明

> 对应：issue #257 / PR #258。本文描述**当前行为与设计取舍**，供维护和下次改动时查阅。

## 三个角色，一套规则

wiki-build 收尾阶段有两个脚本，加上产品的图谱接口，三方必须对「什么算一个链接」有完全一致的口径：

| 角色 | 文件 | 职责 |
|---|---|---|
| `linkpass.mjs` | `apps/daemon/src/tools/skills/wiki-build/scripts/` | 把每个页面名/别名在其他页面正文中的**首次出现**包成 `[[ ]]`；顺手机械清理旧版遗留的坏链接尾巴 |
| `deadcheck.mjs` | 同上 | 收尾门禁：存在指向不存在页面的链接（死链）→ exit 1，构建不算完成 |
| `graph.ts` | `apps/daemon/src/routes/` | 图谱接口：扫同样的 `[[ ]]` 生成节点与连线，未解析目标作为 deadLink 节点入图（Obsidian 同款） |

**核心约定：检查员放行的东西，界面上也不该出问题。** 三方对「代码块里的 `[[...]]` 是字面文本、不算链接」达成一致（与 Obsidian 行为一致）；引文与 frontmatter 里的链接照常渲染，所以照常进图、照常查死链。巡检指引 `wiki-lint` 的断链检查同一口径：grep 数链接不跳过代码块，所以断链的精确判定用 `deadcheck.mjs`，不用 grep 结果。

## 中文词中保护（linkpass，默认开）

英文有词边界，中文没有。两三字的短名字嵌在更长词语中间是常态——「心理」在「核心理念」里、「网络」在「神经网络」里都只是词的一部分，不该建链。

规则：**不超过 3 个字（按码点计）的中文页面名/别名，前后相邻字都是汉字时，视为长词的一部分，跳过不包。**

- **页面名不豁免。**「是不是词中片段」与该名字是不是页面名无关；而且包错的页面名能正常解析（`[[网络]]` 解析到 `网络.md`），deadcheck 判合法、门禁全绿——属于看不见的坏正文，比死链更危险。
- 相邻字按码点取，扩展 B 区汉字（𠀀 等，UTF-16 里是一对代理）也能正确识别。
- 边界判定**透过已有链接看它的显示文字**（`[[甲|乙]]` 按 `乙` 算）。否则邻名被包成链接后插入的 `]]` 会让下一轮误判「不再嵌在词里」又补一条——单次运行必须收敛。
- 恢复旧的全量包裹行为：`--no-cjk-guard`。

### 刻意取舍

- **宁可漏链，不可错链。**「我读红楼梦很多遍」这类句子不再自动建链（红楼梦是 3 字名，嵌在句中）；漏的链接以后能补或人工补，切错的词直接伤正文。
- **跳过首次出现 = 该页对这个名字不再建链**（linkpass 只包真首次出现）。`核心理念先行。后文单独说心理这个词。`——第二处干净出现也不会补包。这是保持单次运行幂等的必要设计：改包后一处，下一轮又会把更后一处当成「首次」。

## 撞名规则

某个词**既是页面名、又是另一页的别名**时（如页面 `网络.md` 存在，而批次里又登记了「网络 → 计算机网络」）：

- **页面优先**：`[[网络]]` 本就解析到 `网络.md`，与 deadcheck 口径一致；
- 撞名别名不参与包裹，记入运行报告的 `collidedAliases`，提示 curate 时改掉；
- 不这样处理的话，两条链接会叠在同一处文字上，现场生成 `[[计算机网络|网络]]网络]]` 坏尾巴——这条规则关掉的是残渣的**生成源**。

## 坏尾巴清理（linkpass，每次运行自动做）

旧版 linkpass 留下的 `[[T|Y]]Y]]`（`]]` 后紧跟「别名`]]`」）只可能是坏内容，机械 collapse 成纯文本 `Y`：

- **保护区不碰**：frontmatter、代码块、行内代码、引文（「」『』""''）逐字节保留——引文要供 `prep.mjs verify` 核验，代码块里的字面值常常是**在讲解这个模式本身**。
- 连环嵌套（`[[甲|乙]][[甲|乙]]乙]]]]`）在单次运行内循环清净；**20 层封顶**，撞上限且仍有剩余的文件记入运行报告 `residueTruncated` 并提示再跑一遍（第 20 轮后会多看一眼确认，恰好 20 层不误报；真实数据只有 1~2 层，正常碰不到）。
- `residueFixed` 按**层**计数：一个两层嵌套记 2。
- `--dry-run` 不写盘，输出如实说「would clean」。

## deadcheck 口径

- **死链**：exit 1。修复方式：补页（可以是占位 stub）或把链接改成已存在的页面/纯文本。
- **代码块/行内代码里的 `[[...]]` 不算链接**（字面文本，不渲染），不会误判死链。
- **引文/frontmatter 里的死链照常拦下**（渲染时仍是链接）。这些区域所有自动工具一个字都不能动（要供 `prep.mjs verify` 逐字节核验），所以**唯一出路是补一个页面**。
- **坏尾巴分两桶报告、都不拦门禁**：正文里的（下次 linkpass 自动清理）与保护区内的（单独计数 `residueProtected`，只提示、不自动清理，需要时手工处理）。`--json` 明细上限 100 条。

## 两份实现与防漂移

保护区间/残渣识别等公共规则抽在 `scripts/lib/linktext.mjs`，linkpass 与 deadcheck 共用。图谱一侧没法直接用它——技能脚本要在裸 node 下运行（不能 import TS），而 daemon 的 tsc 构建未开 allowJs（不能 import .mjs）——所以 `apps/daemon/src/core/wikilink-text.ts` 是它的 TS 孪生。

**防漂移机制**：`apps/daemon/test/core/wikilink-text.test.ts` 用同一批 fixture（围栏、未闭合围栏、行内代码、CRLF、扩展 B 区字符等）双跑两份实现并逐字节对比区间——哪边改了规则，另一边立刻红。改动任一份时，请同步另一份。

## 版本约定

wiki-* 五件套（build/query/ingest/save/lint）同版本号共进：改任一 skill，五个 `version:` 一起 bump 到同一下一个版本；**同一 PR（或一次对外发布）内的连续修订只 bump 一次**（同步本身按内容哈希镜像到既有 vault，version 只作诊断/约定）。
