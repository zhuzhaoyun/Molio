# E2E 残留缺陷修复设计

## 背景

E2E 端口平移迁移后，全量套件剩下 5 个与迁移本身无关的失败。它们分属两类：两个产品缺陷、三个测试用例缺陷。本改动逐项修复，不并入口径迁移，也不改断言强度来换取通过。

## 修复项

### 1. Windows 下「保存到知识库」失败

`SaveToKbButton` 直接取回答首行作为文件名。常见英文回答 `Hello, how can I help you?` 含 Windows 禁止的 `?`，导致写文件失败，新手引导停在 4/5；同一文件名在 Linux 可正常写入。

修复：清洗标题时复用 `slugifyTitle`，统一处理 Windows 禁止字符、控制字符、空白和首尾符号；清洗后为空仍回退为「AI 回答」。

回归：`onboarding.spec.ts` 的完整 1/5 → 5/5 流程；`chat-save-kb.spec.ts` 的保存与无库禁用用例。

### 2. 历史产出面板用例在 Windows 永不命中路径

`session-output-history.spec.ts` 把含反斜杠的绝对路径直接插入 CSS 属性选择器。CSS 字符串会消费 `\T` 等转义，使选择器与实际 `data-path` 不一致。

修复：插入选择器前转义反斜杠与双引号；库内产出与库外排除两条断言使用同一 helper。

回归：历史会话打产出面板、恢复写入列表并定位工具步。

### 3. 登录快照未决时点账号入口，落到错误页面

已登录用户在整页加载后、`authStore` 首次状态尚未返回时点击账号入口，会先误开登录弹窗。快照返回后的兜底原一律导航 `/resources`，覆盖了本次「进入我的页面」的点击意图。

修复：无登录意图的兜底改导航 `/me`；下载/购买等登录意图仍续接原动作；刚完成登录后的 `/resources` 默认落地逻辑不变。

回归：`market-community.spec.ts` 用可控 gate 拦住整页加载后的 `auth/status`，点击账号入口后先断言未决态弹窗（`account-loading`）可见，再放行并断言 `/me`，随后继续原有发布门禁流程。该断言同时锁住 gate 本身：一旦拦截失效、快照提前落定，用例会红，而不是静默退化成普通已登录路径。

### 4. 暗色局部图用例在首图未就绪时切换 scope

`graph-scope-loading` 的语义是「旧图仍在屏上，新 scope 正在加载」。原用例只等 `graph-scope-back` 出现就切换 scope；该按钮只表示已进入局部图 tab，不代表首图数据已返回。首图未返回时走首屏 loading、不显示 chip 是正确行为。

修复：切换前等待首图的搜索入口出现；该入口只在有图数据时渲染，确保测试确实覆盖「已有旧图」的分支。深色背景色断言保持不变。同文件的亮色在途用例前置条件相同，同步补上同一等待——否则「首屏无芯片」一半是恒真的，切 scope 也可能没有旧图可配芯片。

### 5. 悬浮按钮第二次拖拽实际未达到拖拽阈值

按钮第一次唤回后已经贴着右缘。原用例第二次拖拽的横向位移只有 4px，低于组件 6px 的拖拽阈值，因此被识别为点击并打开面板；按钮随面板隐藏，后续断言报「元素不存在」。

修复：第二次拖拽目标更靠近右缘，使位移明确超过阈值。磁吸、隐藏、唤回和重载保持的原有断言全部保留。

## 验证

变基到端口平移迁移之后（origin/main `966e9e9f`）复跑：

- 5 个原失败用例实跑通过（亮色在途用例隔离连跑 2/2，排除首次运行 vite 冷启动造成的首屏超时）；
- `chat-save-kb.spec.ts` 2/2、`auth.spec.ts` 10/10 通过；
- `bootstrap.spec.ts` + `navigation.spec.ts` 13/13 通过；
- Web 单测 738/738，TypeScript 类型检查通过。

只包含上述产品缺陷与对应回归测试。E2E 地址相对化、端口 env 模板及端口守卫属于独立迁移改动，不在本文档和本提交中重复引入。
