知识图谱构建工具有哪些？按 5 个环节选，附工具清单

2026-10-24知识工程

知识图谱构建工具有哪些推荐？没有一份通用榜单，因为构建图谱至少有五件事：建模、抽取、存储、应用和可视化。建模先看 Protégé；中文抽取看 DeepKE、HanLP；属性图存储看 Neo4j、NebulaGraph、HugeGraph、TuGraph，RDF 路线看 Apache Jena、GraphDB；做 GraphRAG 看 Microsoft GraphRAG、LightRAG 和 Neo4j LLM Graph Builder。

下面按这五个环节说明每个工具适合什么、不适合什么。最后给一张按场景选的表，以及一条“不建图”的替代路径。

先选路线，再选工具

工具名不是起点，路线才是。路线选错，后面换工具只是把返工推迟。

路线适合什么
RDF / OWL标准语义、推理、跨系统交换
属性图多跳关系、路径和网络结构
GraphRAG大模型基于文档做全局问答
成品 Wiki 图谱只要成品 Wiki 图谱，不想自己建系统

代表工具分别是：RDF / OWL 看 Jena、GraphDB；属性图看 Neo4j、NebulaGraph；GraphRAG 看 Microsoft GraphRAG、LightRAG；成品 Wiki 图谱看 Molio（墨流）资源库。

这四条路线的代价不一样。RDF 建模门槛高，查询和工程链路更长；属性图要先设计节点、边和属性；GraphRAG 的抽取质量和索引成本决定效果；成品 Wiki 图谱不是图数据库，不能跑 SPARQL 或 Cypher。

如果你还没想清楚这四者的区别，先回到问题本身：你要的是“能查询的图”，还是“能回答问题的资料”？这两个答案会把你带到完全不同的工具上。

建模：Protégé 仍然是起点

Protégé

Protégé 是斯坦福大学开发的免费开源本体编辑器，支持 OWL。它适合定义类、属性、关系和约束，也适合在动手写代码前把领域模型想清楚。

Protégé 的价值不在“画图”，而在逼你把概念之间的关系说清楚。一个类是不是另一个类的子类，一个关系有没有定义域和值域，两个概念能不能同时成立，这些问题在 Protégé 里都要给出答案。模型没想清楚，换什么数据库都一样。

WebProtégé

WebProtégé 是浏览器里的协作版本，适合多人一起改本体、做评审。它的功能和桌面版不完全一样，团队协作前先确认版本、权限和导出格式。

什么时候不需要 Protégé

如果你做的是简单的属性图，实体类型和关系类型不多，不必先上一套 OWL。先用一张表写清节点类型、边类型和属性，再在 Neo4j 里建约束，可能更快。Protégé 适合“语义要严谨”的场景，不适合所有项目。

一个实用的起点是：先列 10 个实体类型、20 条关系，拿 20 个真实样本走一遍。走不通，再回去改模型，不要一开始就设计一个大而全的本体。

抽取：中文文本先看 DeepKE 和 HanLP

DeepKE

DeepKE 是浙江大学开源的知识图谱抽取工具包，覆盖命名实体识别、关系抽取、属性抽取等任务。可以用它做中文知识抽取的研究和原型，也可以把它当作自己训练抽取模型的起点。

DeepKE 不是“装上就能抽准”的按钮。你需要准备标注数据或合适的预训练模型，还要按自己的领域评估效果。论文里的指标不等于你语料上的指标。

HanLP

HanLP 是面向中文的自然语言处理工具，提供分词、词性标注、命名实体识别、依存句法等功能。中文文本的预处理和基础抽取，是它的常见用法，工程可用性比研究型工具更好。

商用前先核对当前版本的许可和支持范围。中文领域词、古文、专业术语，最好拿自己的样本测一遍，不要只看通用演示。

spaCy

spaCy 是 Python 生态里常用的工业级 NLP 库，支持命名实体识别、词性标注、依存句法、词向量等。生态成熟，接进现有 Python 服务比较顺。

spaCy 的通用模型对中文专业领域的覆盖有限。领域实体往往需要自定义训练或规则补充。它的优势是工程链路顺，不是“开箱即懂你的领域”。

LangChain 的 LLM Graph Transformer

LLM Graph Transformer 用大模型从文本里抽节点和关系，适合快速做原型。你给它文档和 schema，它输出结构化的图文档，再写入图数据库或做后续处理。

它的问题也很直接：成本、稳定性和一致性。同一段文本跑两次，结果可能不同；模型还可能抽出你没定义的实体类型。生产使用前，先用 100 条样本评估准确率和召回率，再决定要不要扩大规模。

存储与查询：属性图还是 RDF

Neo4j

Neo4j 是属性图数据库的代表，用 Cypher 查询，生态成熟，文档、驱动和可视化工具都比较完整。多跳关系查询、路径分析和把图谱接进应用，是它的常见场景。

Neo4j 有社区版和企业版，能力与许可不同。选之前先确认你要的功能在哪个版本，不要默认社区版能覆盖生产需求。

NebulaGraph

NebulaGraph 是开源的分布式图数据库，使用 nGQL 查询，适合数据量和并发较大的场景。扩展性是它的长处，代价是部署和运维更复杂。

小团队、小数据量，先用 Neo4j 或单机方案往往更省事。不要为了“以后可能很大”提前承担分布式系统的复杂度。

Apache HugeGraph

Apache HugeGraph 是 Apache 社区的开源图数据库，支持 Gremlin，适合需要图查询和国产开源生态的项目。使用前看当前版本、文档和社区活跃度，确认它和你的技术栈匹配。

TuGraph

TuGraph 是蚂蚁集团开源的高性能图数据库，适合对查询性能有要求的场景。它的生态和工具链与 Neo4j 不完全一样，选型时要把驱动、运维和团队熟悉度一起算进去。

Apache Jena

Apache Jena 是构建语义网和关联数据应用的 Java 框架，支持 RDF、SPARQL 和 TDB。走 RDF/OWL 路线、需要标准查询和推理的项目，会用到它。

Jena 是框架，不是一站式产品。你要自己搭存储、查询和服务层，工程能力要求比“装一个图数据库”更高。

GraphDB

GraphDB 是支持 RDF 和推理的图数据库，使用 SPARQL 查询，适合本体较重、需要语义推理的场景。它有不同版本，功能和许可需要按项目核对。

Stardog

Stardog 定位为知识图谱平台和语义层，支持 SPARQL、推理和数据虚拟化，适合企业里要把多个数据源连起来做统一语义查询的场景。它是商业产品，选型时要把成本和落地周期算进去。

GraphRAG：把图谱接到大模型上

Microsoft GraphRAG

Microsoft GraphRAG 是一个模块化的、基于图的 RAG 系统。它从文本里抽取实体和关系，构建社区摘要，再支持局部查询和全局查询。需要对一整个语料库做总结、比较和跨文档回答时，它是合适的选择。

它的代价在索引。抽取、建图、生成社区摘要都要花时间和模型调用，语料越大越明显。它不是“装上就比向量检索聪明”，抽取质量和语料结构决定上限。

LightRAG

LightRAG 是一个更轻量的 GraphRAG 实现，强调简单和快速，提供双层检索。想快速验证“图谱加检索”的效果，可以从它开始。

轻量不等于免费。你仍然要处理文档切分、实体抽取、存储和评估。先用一小批语料跑通，再扩大。

Neo4j LLM Graph Builder

Neo4j LLM Graph Builder 用大模型从非结构化文本里抽节点和关系，写入 Neo4j。已经在用 Neo4j、想把文档变成图的团队，用起来更顺。

它的效果取决于 schema 和模型。不要直接把整本书丢进去就期待一张干净的图。先定义实体类型和关系类型，再分批处理。

LlamaIndex PropertyGraphIndex

LlamaIndex 的 PropertyGraphIndex 在 LlamaIndex 里构建属性图索引，适合已经把文档处理和检索放在 LlamaIndex 里的项目。它把图索引接进现有的 RAG 链路，减少自己拼装的工作。

可视化与分析：最后再选

Gephi

Gephi 是开源网络可视化与分析软件，适合探索图结构、看社区和中心节点。它适合分析和展示，不适合做生产系统的前端。

Cytoscape

Cytoscape 是开源网络分析与可视化平台，起源在生物信息学，也能处理一般网络数据。插件生态能做探索性分析。

NetworkX

NetworkX 是 Python 图分析库，适合算中心性、社区、路径和做实验。它不以可视化为第一目标，通常和 Matplotlib、Gephi 或前端图表配合使用。

ECharts

Apache ECharts 是浏览器端的可视化库，支持关系图。把图嵌进网页或产品界面可以用它，交互和样式可控，但需要自己处理布局和数据量。

这张表是选型起点，不是性能排名。真实项目还要看数据量、团队技能、预算、许可和运维能力。

如果你不想从零构建

工具解决的是“怎么建”，但很多人真正的问题是“我没有内容”。这两件事可以分开处理。

Molio（墨流）资源库走的是另一条路：把某个主题的实体、概念、事件和关系整理成 wiki 双链图谱，交付为 Markdown 文件。解压后可以用 Molio 或 Obsidian 打开，也可以交给能读本地文件的 Agent。打开一个条目，可以顺着双链跳到相关条目；Molio 的图谱对照会把关联节点显示在旁边。

它不是图数据库，也没有 SPARQL 或 Cypher 查询，所以不能拿来替代 Neo4j 或 Jena。它的强项是双链导航和关系视图，不是程序化查询。

它适合的场景很具体：你要读一个领域、查人物和概念之间的关系、给 AI 一份有结构的上下文，但不想先花几个月做抽取和建模。比如：

  • 知识工程全景图谱：围绕本体、RAG、GraphRAG 和 Agent 工程整理概念，适合先建立整体框架。
  • 史记知识库：按人物、制度与思想组织《史记》，适合查关系。
  • 中西哲学思想图谱：整理哲学家、核心概念与思想对比，适合做概念对照。

常见问题

这些构建工具里哪些是开源的？

Protégé、DeepKE、Apache Jena、NebulaGraph、Apache HugeGraph、TuGraph、Microsoft GraphRAG、LightRAG 都有开源版本。Neo4j 有社区版和企业版，GraphDB、Stardog 也有不同版本。具体许可以官方仓库或产品页为准，商用前要单独核对。

新手先学 Neo4j 还是 Protégé？

看你要解决什么问题。要做属性图查询和路径分析，先学 Neo4j 和 Cypher；要定义本体、类和约束，先学 Protégé 和 OWL。两个都学也可以，但不要在没有场景的情况下背工具。

只做文档问答，需要图数据库吗？

不一定。文档量不大、问题主要是局部事实时，向量检索加普通 RAG 可能已经够用。问题涉及跨文档关系、全局总结、多跳推理时，再考虑 GraphRAG 或图数据库。先测再选，不要为了“图谱”而图谱。

中文知识抽取用什么工具？

可以从 DeepKE、HanLP 或 spaCy 起步，也可以用 LLM Graph Transformer 做快速原型。关键不是工具名，而是你有没有领域样本和评估标准。先用 100 条真实文本比较准确率和召回率。

Molio 的资源能直接导入 Neo4j 吗？

不能一键导入。它是 wiki 双链图谱，交付为 Markdown 文件，不是 Neo4j 的导出文件，也不是 RDF 三元组。要用在图数据库里，需要自己解析页面和双链、设计节点和边，再写入。它更适合直接阅读、顺着双链查，以及给 AI 提供上下文。
