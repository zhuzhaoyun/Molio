知识图谱资源网站有哪些？10 个入口，按数据、工具、成品选

2026-10-24知识工程

知识图谱资源网站有哪些？先想清楚你要的是数据、工具，还是成品。要查开放数据，先看 Wikidata、DBpedia、OpenKG 和 CN-DBpedia；要做中国历史人物研究，先看 CBDB 和 ctext；要直接读一张已经连好的 wiki 双链图谱，可以看 Molio（墨流）知识图谱资源库。

下面按“数据”和“成品 Wiki 图谱”展开。每一类说清三件事：它能给你什么，它不适合什么，第一次打开时先做什么。这样你就不用在一个个“知识图谱大全”里反复试错。

先分清你要数据、工具，还是成品 Wiki 图谱

“知识图谱资源”这五个字，容易被当成一种东西。实际上，搜这个词的人可能在找三种不同的东西。

类型它是什么，适合什么
数据与资料开放图谱、领域数据库、CSV/JSON；适合查询、分析、自己建模，不一定是知识图谱，也不等于开箱即用
图谱工具建模、抽取、图数据库、可视化软件；适合自己构建系统，不提供领域内容
成品 Wiki 图谱实体页、双链、关系视图；适合直接阅读、检索、给 AI 用，不是图数据库，不能跑 SPARQL 或 Cypher

先想清楚你要的是“查数据”，还是“自己建”，还是“直接读一张已经连好的 Wiki 图谱”。答案不同，入口完全不同。工具那一条，另开一篇讲；这篇重点讲数据和成品。

开放知识图谱：要能查询、能下载三元组，先看这四个

Wikidata：跨语言实体查询的起点

Wikidata 是一个开放、多语言的知识库。每个实体有一个稳定的 Q 编号，人和机器都能读，也能通过 SPARQL 查询。它最适合做跨语言实体对齐，比如把“孔子”“Confucius”和不同语言里的同一实体对应起来。

边界也要提前知道。Wikidata 的覆盖广，但领域深度取决于社区贡献。你要研究一个很细的专业问题，它未必有足够细的关系和出处。上手时先拿一个熟悉的实体，看它的属性、来源和关联实体，再决定要不要往下做。

DBpedia：从维基百科抽出来的结构化数据

DBpedia 把维基百科里的信息抽取成结构化数据，提供数据集、工具和查询服务。通用实体的结构化查询是它的主场，也常被用来做知识图谱研究和应用原型。

DBpedia 的更新节奏跟着维基百科和抽取流程走，页面上的信息变了，数据集不一定同步。它的本体映射也需要花时间理解。可以先用一个常见实体试查，看看它有哪些属性、哪些属性是空的，再判断它能不能支撑你的问题。

OpenKG：中文开放图谱的数据集入口

OpenKG 是中文开放知识图谱社区，聚合了数据集、工具和相关资料。找中文领域的开放图谱，可以从这里入手，尤其是通用图谱之外的专业数据集。

OpenKG 更像一个入口，而不是一份统一标准的数据产品。不同数据集的格式、质量、许可和维护状态差别很大。下载前先看数据集说明、更新时间和许可条款，不要只看名字。

CN-DBpedia：中文通用实体与关系

CN-DBpedia 是复旦大学知识工场整理的中文通用知识图谱，提供中文实体与关系的检索入口。中文实体查询、关系抽取和信息验证，可以把它当起点。

使用前同样要看当前的服务方式、数据版本和许可。通用图谱对热门实体覆盖更好，对冷门领域未必够用。不妨先用一个熟悉的领域实体试查，看看关系的颗粒度，再决定是否继续。

领域数据库：做历史研究，不要只搜“知识图谱”

如果你研究的是中国历史、古籍或人物关系，通用知识图谱往往不够细。这时候要找的不是“更大的图谱”，而是领域数据库。

CBDB：中国历代人物传记资料库

CBDB 是中国历代人物传记资料库，围绕人物、官职、亲属关系、社会关系等维度整理资料。这些字段能回答一个人是谁、担任过什么职位、和谁有亲属或社会关系，也适合做群体研究。

要注意，CBDB 是关系型数据库，不是一张可以直接拿去做图计算的 RDF 图谱。真正的价值在资料和字段，之后怎么变成节点和边，仍然需要你自己建模。

ctext：古籍原文检索与对照

ctext 是中国哲学书电子化计划，提供大量古籍原文的检索和阅读。你可以查一句话出自哪一篇，对比不同版本，顺着上下文核对词义。

ctext 解决的是“原文在哪”，不是“人物和制度之间是什么关系”。你可以用它核对出处，但关系仍然要自己抽。把 ctext 当图谱用，会失望；把它当出处库用，很有价值。

中研院汉籍电子文献

中研院汉籍电子文献 提供大量中国古籍的全文检索。版本核对、词句检索和史料定位，是它的用途。部分资源可能需要机构授权或注册，使用前先看站点说明。

这类数据库的共同点是：资料权威，但结构不一定适合机器直接消费。你要自己做实体识别、关系抽取和出处对齐。这也解释了一个常见困惑：为什么手里有很好的资料库，还是做不出好用的知识图谱。

数据集与代码：适合已经决定自己建的人

Hugging Face Datasets

Hugging Face Datasets 上有大量与知识图谱相关的数据集，格式包括三元组、问答、抽取任务数据等。做模型训练、评测和快速实验时会用到它。

下载前先看数据集卡片：字段是什么，许可是什么，版本是什么，有没有已知问题。不要只看下载量。一个数据集的名字里有“knowledge graph”，不代表它适合你的任务。

GitHub Topics

GitHub 的 knowledge-graph 话题 聚合了开源项目、工具和示例。找实现代码、参考架构和可复现实验，可以看这里。

开源项目的维护状态差别很大。第一次看，先看最近提交、issue 回复、许可证和文档完整度。一个几年前的项目还能跑，不代表它适合放到生产环境。

成品 Wiki 图谱：不是数据库，是双链知识网

最后一类是成品 Wiki 图谱。它不是让你自己建模的工具，也不是原始三元组数据集，而是把某个主题的实体、概念、事件、制度整理成一个个 Wiki 页面，再用双链把这些页面连起来。你打开一个条目，可以顺着链接跳到相关条目；Molio 的图谱对照会把当前条目的关联节点显示在旁边。

Molio（墨流）资源库属于这一类。这一段是自述，不是第三方评测。它把《史记》《资治通鉴》、中西哲学、知识工程等主题整理成 wiki 双链图谱，交付为 Markdown 文件，解压后可以用 Molio 打开，也可以用 Obsidian 打开，还可以放进 Claude Code、Codex 这类能读本地文件的 Agent 的工作目录。部分资源会标原文位置，方便回到出处核对。

边界要说清楚。它不是图数据库，不能执行 SPARQL 或 Cypher；也不是拿来训练模型的原始三元组数据集。它的强项是双链导航和关系视图：让人顺着人物、事件、概念之间的关系读下去，也让 AI 拿到一份有结构的上下文。

三个常见误区

把百科当图谱。 百科词条是给人读的条目，不是带关系、带出处、可批量查询的三元组。你可以用百科做背景阅读，但不要把它当成知识图谱数据集。

把数据集当成品，或把 Wiki 图谱当图数据库。 数据集给你原料，不给你字段说明、清洗流程和关系设计；Wiki 图谱给你的是已经连好的页面，不是可供程序查询的图数据库。两种错位都会让你对交付物产生错误预期。

只看数量，不看版本和许可。 一个图谱有多大，不如它覆盖什么、更新到什么时候、许可能不能支撑你的用途。尤其是要商用或再分发时，先看条款，不要凭印象。

常见问题

这些资源网站都免费吗？

开放图谱和领域数据库大多提供免费访问，但具体到某个数据集、接口或批量下载，可能有许可和频率限制。商用或再分发前，逐一查看站点当前的许可说明。

Wikidata 和 DBpedia 有什么区别？

Wikidata 是持续编辑的开放知识库，实体有稳定的 Q 编号，适合跨语言查询和实体对齐。DBpedia 是从维基百科抽取出来的结构化数据，适合通用实体的结构化查询，但更新节奏跟随抽取流程。两者可以互补，不是互相替代。

只想找中文知识图谱数据集，先去哪？

先看 OpenKG 和 CN-DBpedia。OpenKG 更像数据集入口，适合找不同领域的中文图谱；CN-DBpedia 是中文通用实体与关系的检索入口。下载或接入前，先核对版本、字段和许可。

Molio 的资源是知识图谱数据库吗？

不是图数据库，而是 wiki 双链图谱。它以人物、事件、概念、制度等为页面，用双链把页面连成一张可导航的关系网；交付为 Markdown 文件，可以在 Molio、Obsidian 或本地 Agent 里打开。它不提供 SPARQL 或 Cypher 查询，也不是原始三元组数据集。

没有技术背景，能用这些资源吗？

能，但要看选哪一类。ctext、CBDB 的检索界面和成品 Wiki 图谱可以直接用；自己下载数据集、建图、写查询，则需要建模和数据处理能力。先按任务选类型，不要一上来就选最复杂的方案。
