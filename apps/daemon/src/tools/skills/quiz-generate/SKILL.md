# quiz-generate: 从知识库出题

从**当前知识库**生成可作答、可判分、可溯源的题目（客观题、填空题与解答题）。内容必须来自库，不得凭训练记忆出题。

## 触发

用户说「出题 / 考考我 / 练习 / 刷题 / 测验 / 给我几道题 / 模拟考 / quiz / practice / test me」，或点名 `/quiz-generate` 时使用。

## 流程（必须按顺序）

### 1. 先检索

按 `wiki-query` 的路径定位材料：

1. 读 `wiki/hot.md`（存在时）
2. 读根 `wiki/INDEX.md`
3. 按需读相关目录的 `INDEX.md`
4. 读 2–5 个最相关的 wiki 页面
5. wiki 不足时回溯源文件（`raw/`、`notes/`、`docs/` 等）

禁止只凭训练记忆出题。材料不足时明确告诉用户「这个主题在库里覆盖不足」，并少出题或不出题。

### 2. 确定范围

- 默认：整个库
- 用户指定文档/文件夹/主题：只在该范围出题
- 用户指定题量/题型/难度：按指令调整
- 未指定：默认 5 题，单选为主，可搭配多选、判断和填空；说理/证明类内容适合解答题

### 3. 领域自适应

先看材料的知识形态，再决定题型。不要套固定考纲，也不要假设学科。

| 知识形态 | 适合的题 |
|---|---|
| 概念/定义 | 辨析、反例判断、术语匹配 |
| 流程/步骤 | 顺序判断、下一步选择、异常处置 |
| 条件/规则 | 条件组合、适用边界、正反例 |
| 因果/时间 | 因果判断、时间线排序、影响推断 |
| 计算/参数 | 计算题、单位判断、边界条件 |
| 观点/论证 | 立场判断、论据匹配、反驳识别 |
| 语言/用法 | 用法辨析、搭配判断、翻译选择 |

题型只是手段。题目要考「是否理解材料」，不要考材料里没有的细节。

### 4. 生成

每题必须满足：

- `stem` 自包含，不依赖上一题
- 数学与符号用**纯文本记法**书写（√ x² aⁿ π 10⁻³）：不要输出 LaTeX 源码（`$…$`、`^`、`_`）——答题区按原样显示，源码会直接暴露给用户
- 配图只由考点决定，不预设学科比例：某题**必须看图才能作答或成立**时，题干才嵌库内图片 `![说明](相对路径.png)`（路径相对**知识库根**、不带前导 `/`、文件必须真实存在，png/jpg/gif/webp/svg 等）；文字能说清就不配图，装饰性配图一律不做。**双向锁**：写了「如图/下图」就必须真嵌了图；没嵌图就绝不写「如图」。不要写绝对路径或网络 URL
- 选项互斥、无歧义；单选/多选 2–8 项
- 单选/多选/判断：`answer` 的 key 必须存在于选项中；单选/判断恰好 1 项，多选至少 2 项（填空题不同，见下方额外规则）
- `explanation` 说明为什么对/为什么错，可引用材料
- `sources` 至少 1 条，`path` 是 vault 相对路径；能找到原文时填 `quote`
- 不跨题重复，不考材料未覆盖的细节
- 找不到依据就不出这道题，宁可少出

填空题（`type: "fill"`）额外满足：

- 只考回忆式记忆点：术语、数值、关键短语；不考需要整段作答的内容
- 一题一空，空位在 `stem` 里用 `____` 标注
- `answer` 是可接受写法数组：第 1 项是标准答案，其余是同义写法（1–8 项、每项不超过 64 字符）
- 答案含键盘不易输入的字符时（√ π ≤ Ω ° 等，任何领域），写法数组必须含一个纯键盘可打的变体（如 `["√2/2", "sqrt2/2", "sqrt(2)/2"]`）；**变体不得改变考察点**——难输入字符本身就是考点时（如外语考音符拼写、文字学考繁体字），不给降级变体，让用户用答题区的符号面板输入
- 出题优先选答案不需要生僻符号的空
- 简答/解答/论述不是填空，走下面的「解答题」规则进围栏

解答题（`type: "subject"`）额外满足：

- 考「说理 / 证明 / 论述 / 多步应用」这类需要整段作答的内容——填空装不下、选项会泄底的题
- 没有 `options`；`stem` 把作答要求说完整（证明什么、论述什么、要给出哪些步骤）
- `answer` 是**评分点**数组：1–8 条、每条不超过 200 字符，**每条自足成句**——它会脱离对话上下文单独展示给批改方，不得写「见上 / 同上」这类指代
- 评分点拆到「可独立判对错」的粒度：一条只说一个步骤或一个要点

### 5. 输出

只输出**一个**引导句 + **一个** `quiz` 围栏。围栏外不得出现答案、解析或题目清单。

```quiz
{
  "version": 1,
  "title": "主题 · N 题",
  "questions": [
    {
      "id": "q1",
      "type": "single",
      "stem": "题干",
      "options": [
        { "key": "A", "text": "选项 A" },
        { "key": "B", "text": "选项 B" }
      ],
      "answer": ["B"],
      "explanation": "解析。",
      "sources": [
        { "path": "wiki/concepts/示例.md", "quote": "原文摘录" }
      ]
    },
    {
      "id": "q2",
      "type": "fill",
      "stem": "____是标准番茄钟的专注时长（分钟）。",
      "answer": ["25", "二十五"],
      "explanation": "解析。",
      "sources": [
        { "path": "notes/示例.md" }
      ]
    },
    {
      "id": "q3",
      "type": "subject",
      "stem": "论述番茄工作法为什么强调「一个番茄钟不可分割」，给出至少两条理由。",
      "answer": ["说明打断会破坏专注周期的完整性", "指出半个番茄钟无法计入已完成统计", "结合材料里的执行反馈机制给出论证"],
      "explanation": "按评分点逐步给分。",
      "sources": [
        { "path": "wiki/示例.md" }
      ]
    }
  ]
}
```

格式要求：

- 合法 JSON：双引号、无注释、无尾逗号
- 字符串内换行写成 `\n`
- `type` 只能是 `single` / `multiple` / `judge` / `fill` / `subject`
- `judge` 可省略 `options`，省略时等价于 A=正确、B=错误
- `fill` 没有 `options`，`answer` 是可接受写法数组（第 1 项=标准答案）
- `subject` 没有 `options`，`answer` 是评分点数组（每条自足成句）
- `title` 简洁，不带学科预设

### 批改协议（大题作答）

web 端把主观题作答物化成一条含 `【大题作答·第N题】` 标记行的消息，标记行之后依次是题干、评分点、出处与用户作答（标记行通常在消息开头；前面可能被宿主拼入图片附件或上下文前缀）。收到**含该标记行**的消息时按以下协议批改——这是确定性触发，不靠模型自觉判断：

1. 逐评分点判定：命中 / 部分命中 / 未中，并指出作答里对应的依据
2. 出错的步骤要说明错在哪、正确的思路是什么
3. 给分：X/Y（Y = 评分点总数）
4. 讲错因时能引出处就引出处（消息里列出的文档路径）
5. 作答含糊、多种理解都说得通时明说拿不准，不要硬判

批改标准就是消息里列出的评分点，不要自己另立标准或加码。

### 6. 自检

输出前逐题检查：

- [ ] 单选/多选/判断：答案 key 都在选项里；单选/判断只有 1 个答案，多选至少 2 个
- [ ] 每题都有非空 `explanation`
- [ ] 每题至少 1 条 `sources`，路径真实存在
- [ ] 填空题：一题一空、`answer` 是写法数组、每项 ≤64 字符、没有 `options`
- [ ] 解答题：`answer` 是评分点数组（1–8 条、每条 ≤200 字符）、每条自足成句、没有 `options`
- [ ] 没有跨题重复
- [ ] 围栏外没有围栏内题目的答案或解析
- [ ] JSON 能被 `JSON.parse` 解析
