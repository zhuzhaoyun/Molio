# quiz-generate: 从知识库出题

从**当前知识库**生成可作答、可判分、可溯源的客观题。内容必须来自库，不得凭训练记忆出题。

## 触发

用户说「出题 / 考考我 / 练习 / 刷题 / 测验 / 给我几道题 / 模拟考 / quiz / practice / test me」，或点名 `/quiz-generate` 时使用。

## 流程（必须按顺序）

### 1. 先检索

按 `wiki-query` 的路径定位材料：

1. 读 `wiki/hot.md`（存在时）
2. 读根 `wiki/INDEX.md`
3. 按需读相关目录的 `INDEX.md`
4. 读 2–5 个最相关的 wiki 页面
5. wiki 不足时回溯源文件（`raw/`、`notes/`、`docs/` 等）

禁止只凭训练记忆出题。材料不足时明确告诉用户「这个主题在库里覆盖不足」，并少出题或不出题。

### 2. 确定范围

- 默认：整个库
- 用户指定文档/文件夹/主题：只在该范围出题
- 用户指定题量/题型/难度：按指令调整
- 未指定：默认 5 题，单选为主，可搭配多选和判断

### 3. 领域自适应

先看材料的知识形态，再决定题型。不要套固定考纲，也不要假设学科。

| 知识形态 | 适合的题 |
|---|---|
| 概念/定义 | 辨析、反例判断、术语匹配 |
| 流程/步骤 | 顺序判断、下一步选择、异常处置 |
| 条件/规则 | 条件组合、适用边界、正反例 |
| 因果/时间 | 因果判断、时间线排序、影响推断 |
| 计算/参数 | 计算题、单位判断、边界条件 |
| 观点/论证 | 立场判断、论据匹配、反驳识别 |
| 语言/用法 | 用法辨析、搭配判断、翻译选择 |

题型只是手段。题目要考「是否理解材料」，不要考材料里没有的细节。

### 4. 生成

每题必须满足：

- `stem` 自包含，不依赖上一题
- 选项互斥、无歧义；单选/多选 2–8 项
- `answer` 的 key 必须存在于选项中；单选/判断恰好 1 项，多选至少 2 项
- `explanation` 说明为什么对/为什么错，可引用材料
- `sources` 至少 1 条，`path` 是 vault 相对路径；能找到原文时填 `quote`
- 不跨题重复，不考材料未覆盖的细节
- 找不到依据就不出这道题，宁可少出

### 5. 输出

只输出**一个**引导句 + **一个** `quiz` 围栏。围栏外不得出现答案、解析或题目清单。

```quiz
{
  "version": 1,
  "title": "主题 · N 题",
  "questions": [
    {
      "id": "q1",
      "type": "single",
      "stem": "题干",
      "options": [
        { "key": "A", "text": "选项 A" },
        { "key": "B", "text": "选项 B" }
      ],
      "answer": ["B"],
      "explanation": "解析。",
      "sources": [
        { "path": "wiki/concepts/示例.md", "quote": "原文摘录" }
      ]
    }
  ]
}
```

格式要求：

- 合法 JSON：双引号、无注释、无尾逗号
- 字符串内换行写成 `\n`
- `type` 只能是 `single` / `multiple` / `judge`
- `judge` 可省略 `options`，省略时等价于 A=正确、B=错误
- `title` 简洁，不带学科预设

### 6. 自检

输出前逐题检查：

- [ ] 答案 key 都在选项里
- [ ] 单选/判断只有 1 个答案；多选至少 2 个
- [ ] 每题都有非空 `explanation`
- [ ] 每题至少 1 条 `sources`，路径真实存在
- [ ] 没有跨题重复
- [ ] 围栏外没有答案或解析
- [ ] JSON 能被 `JSON.parse` 解析
